fix(settings): make the rail's dirty dot and current section honest

Review round on #82.

The warn dot was `dirty && SERVER_BACKED.has(id)`, so editing any one
server-backed setting lit up all four sections. That says "there are
unsaved edits somewhere" -- which the save bar already says -- while
implying it about three sections you never touched. `dirtyAppSections`
now compares per-section slices, splitting `harness` between Chat (model
and effort defaults) and Context (token limits) since one server key
holds both decisions.

The overall `appSettingsDirty` stays a whole-object comparison rather
than the union of those slices: a field added to AppSettings and not yet
routed to a section would otherwise be editable, unsaved, and invisible.
Worst case is a save bar with no dot beside it, not an edit you can't
save.

It's derived with useMemo rather than through a zustand selector --
building a new Set per call means a selector that never returns a
referentially-equal value, which re-renders on every unrelated store
write and trips React's "getSnapshot should be cached" guard.

Rail rows also carry `aria-current="page"`, so which section you're on is
available as more than a background colour. Nothing is current at `sm`,
where the rail is the index and the detail isn't on screen.

Plus the `AppOverlay` doc comment, which still described `config` and
`settings` as overlays after they became views.
